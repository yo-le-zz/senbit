# 🚀 Senbit 0.5.0 — Recovery Update

**Senbit 0.5.0 est disponible !**

Cette version marque une étape importante dans le développement de Senbit, avec l'arrivée d'un véritable système de récupération, d'une API système, d'un mécanisme de snapshots et de plusieurs améliorations majeures du démarrage et de la gestion des consoles.

L'objectif de cette mise à jour est simple : rendre Senbit plus robuste, plus facile à réparer et plus fiable face aux erreurs système.

---

## 🛠️ API système

Senbit dispose désormais d'une API système centralisée permettant aux commandes et aux composants du système de communiquer avec le service principal.

Le socket système `/run/senbit.sock` prend en charge les requêtes suivantes :

- `ping` — Vérifier que le système répond.
- `version` — Obtenir la version de Senbit.
- `panic` — Déclencher un crash contrôlé du noyau.
- `reboot` — Redémarrer la machine.
- `shutdown` — Arrêter le système.
- `halt` — Arrêter l'exécution.
- `poweroff` — Éteindre la machine.

L'API est documentée dans `docs/API.md`, avec une procédure permettant d'ajouter de nouvelles requêtes.

### 💥 Kernel Panic

La commande `sudo panic` permet désormais de déclencher un véritable Kernel Panic.

Avant l'exécution, une confirmation est demandée afin d'éviter les déclenchements accidentels. L'option `--yes` permet de confirmer directement.

Le système synchronise les données avant de déclencher le crash via l'interface SysRq du noyau.

Un délai de redémarrage automatique est également configuré dans GRUB grâce au paramètre `panic=10`.

En cas de crash, la machine redémarre automatiquement, permettant au système de récupération de reprendre le contrôle.

### 🖥️ Écran de panic

Les Kernel Panic de Rust dans `senbit-init` sont désormais interceptés et redirigés vers un écran dédié :

**SENBIT KERNEL PANIC**

Les erreurs critiques de l'init affichent ainsi un écran explicite au lieu de provoquer un arrêt silencieux ou un message incompréhensible.

## 💾 Système de snapshots

Senbit intègre désormais un outil de sauvegarde et de restauration de la configuration système : `snapshot`.

Il permet de gérer les snapshots directement depuis le terminal.

| Commande | Description |
|---|---|
| `snapshot create` | Créer un snapshot |
| `snapshot list` | Lister les snapshots |
| `snapshot show` | Afficher les informations d'un snapshot |
| `snapshot restore` | Restaurer un snapshot |
| `snapshot delete` | Supprimer un snapshot |

Chaque snapshot sauvegarde notamment :

- La configuration de `/etc`.
- La liste des paquets installés.
- L'état de dpkg.

### 🔒 Restauration sécurisée

Avant chaque restauration, un snapshot de sécurité est automatiquement créé.

Les mises à jour effectuées avec APT déclenchent également une sauvegarde automatique avant leur exécution.

Le système conserve les trois derniers snapshots automatiques, tandis que les snapshots créés manuellement ne sont jamais supprimés automatiquement.

Cette fonctionnalité permet de revenir à une configuration précédente en cas de problème après une modification ou une mise à jour.

## 🛟 Mode Recovery

Une nouvelle entrée **Senbit (recovery)** est disponible dans GRUB.

Elle permet de démarrer Senbit dans un environnement de récupération avec un shell root, via `rescue.target`.

Ce mode est destiné aux opérations de maintenance, de réparation et de récupération du système.

Il permet notamment d'utiliser :

- `snapshot`
- `rollback`
- `apt`

Le mode Recovery réinitialise également le compteur de démarrage, évitant ainsi de déclencher inutilement le mécanisme de rollback.

## 🔧 Réparation depuis l'ISO

L'ISO de Senbit propose désormais une nouvelle entrée GRUB :

**Senbit (repair an installed system)**

Cette fonctionnalité permet de réparer une installation existante directement depuis l'environnement de démarrage.

Le système :

1. Détecte l'installation Senbit présente sur le disque.
2. Effectue un contrôle automatique du système de fichiers.
3. Propose un contrôle approfondi si nécessaire.
4. Monte le système installé.
5. Fournit un shell root dans l'installation.

Depuis cet environnement, il est possible d'utiliser les outils de récupération habituels, notamment `snapshot`, `rollback` et `apt`.

À la sortie du shell, les partitions sont démontées et la machine redémarre.

## 🧹 Vérification du système de fichiers

Senbit effectue désormais un contrôle automatique du système de fichiers au démarrage.

La vérification repose sur `e2fsck -p` et intervient avant le montage de la partition racine.

Elle permet de détecter et de corriger automatiquement certains problèmes provoqués par un arrêt brutal, une coupure de courant ou un crash système.

Les résultats sont intégrés à `bootreport`, dans la section **Filesystem check**.

Un avertissement est affiché lorsqu'une réparation a été effectuée ou qu'un contrôle approfondi est recommandé.

Le démarrage n'est pas bloqué par ce contrôle.

## 🖥️ Consoles supplémentaires

Senbit prend désormais en charge plusieurs consoles virtuelles.

Deux consoles supplémentaires sont activées par défaut :

- `Alt + F2` — Deuxième console.
- `Alt + F3` — Troisième console.

Chaque console dispose de son propre service de connexion, basé sur le nouveau gabarit `senbit-login@.service`.

La création du socket de l'API système reste réservée à la console principale, afin d'éviter les conflits entre les différentes sessions.

Il est également possible d'activer d'autres consoles manuellement :

```bash
systemctl enable --now senbit-login@tty4
```

## ⌨️ Gestion des jobs et du terminal

La gestion des sessions du shell a été renforcée afin de permettre un fonctionnement correct du contrôle des jobs.

Le shell utilise désormais une session dédiée et un terminal de contrôle, grâce à `setsid` et `TIOCSCTTY`.

Cela permet notamment de prendre en charge les opérations classiques :

- Suspendre un processus avec `Ctrl + Z`.
- Reprendre un processus en arrière-plan avec `bg`.
- Reprendre un processus au premier plan avec `fg`.
- Interrompre un processus avec `Ctrl + C`.
