# 🚀 Senbit 0.6.0

Senbit 0.6.0 brings **recovery** and **security**: a Senbit that fails can be repaired without reinstalling it, and a fresh install is safer by default and shows what it exposes.

It adds a recovery boot entry, a repair mode on the ISO, the `snapshot` command, a filesystem check at every boot, a documented system API with a real `panic` command, a default firewall, an exposure report and file integrity checks.

The goal stays the same: a lightweight, reliable Linux server operating system built around standard tools.

## 🛟 Recovery

- **Recovery boot entry**: the GRUB menu now has `Senbit (recovery)`, a root shell with the services stopped. It does not count as a failed boot.
- **Repair from the ISO**: the ISO has an entry `Senbit (repair an installed system)`. It finds the installed Senbit, checks its filesystem, mounts it and gives a root shell inside it. `exit` unmounts everything and reboots.
- **`snapshot` command**: `snapshot create`, `list`, `show`, `restore` and `delete` for the configuration (`/etc`), the package list and the dpkg state. A safety snapshot is taken before every restore, and apt takes one before every upgrade (the last 3 are kept).
- **Filesystem check at every boot**: `e2fsck -p` runs on the root partition before it is mounted. The result is in the boot report.
- **`panic=10` on every boot entry**: after a kernel panic the machine reboots by itself, so the boot counter and the automatic rollback can do their work.

## 🔌 System API and `panic`

- The socket used by the power commands is now a documented **system API** (`docs/API.md`), with `ping` and `version` requests.
- **`sudo panic`** triggers a real kernel panic, to test that a crash is survived.
- A **panic hook** for every native command: one clear message, where to report the bug, exit status 70.
- A Rust panic in `senbit-init` now shows the Senbit panic screen instead of killing PID 1 silently.

## 🖥️ Consoles

- Two more logins on **Alt+F2** and **Alt+F3**. Job control (`Ctrl+Z`, `bg`, `fg`) works in every console.

## 🛡️ Security

Documented in `docs/SECURITY.md`:

- **Default firewall**: nftables is part of the image. Inbound traffic is denied except answers, loopback, ping, DHCP and SSH. Your own rules go in `/etc/senbit/firewall.d/`.
- **`bootreport --ports`**: what listens on the network, and which process. The login banner says how many ports are reachable.
- **`bootreport --verify`**: Senbit files modified since the packages were installed. The check runs once per boot and the login banner warns when something changed.
- **Hardening defaults**: sysctl settings, and no direct root login over SSH.
- **`sudo` lockout** after five wrong passwords.
- Optional **automatic upgrades** (`senbit-auto-upgrade.timer`, off by default).

## 🌐 Website and documentation

- New website at https://senbit.pages.dev.
- Documentation rewritten and corrected: architecture, installer, running system, systemd, development, updates, API, security.
- New roadmap, organized by capability: recovery and security, declarative deployment, real hardware.
- A cleaner build: the initramfs is rebuilt only when the root filesystem changed, and compressed faster.

## ⚠️ Known Limitations

- The checksums used by `bootreport --verify` are known to dpkg only after the Senbit packages were installed through apt.
- The recovery entry relies on the BusyBox `sulogin`.
- Debian's `nftables.service` must stay disabled: it flushes every rule, including Senbit's.
- Docker Engine networking is still to be confirmed.

Further testing and improvements are ongoing.
