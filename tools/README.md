# 🛠️ Senbit Build Tools

The `tools/` directory contains **Rust tools used to prepare and generate resources required to build Senbit**.

These tools are not part of the system running on Senbit. They are only used during the build process.

## 📁 Structure

```text
tools/
├── README.md
│
├── keymaps/
│   ├── Cargo.toml
│   └── src/
│       └── main.rs
│
└── ...
```

Files generated by these tools are stored in `build/tools/generated/`:

```text
build/
└── tools/
    └── generated/
        └── keymaps/
            ├── fr.bmap
            ├── us.bmap
            └── ...
```

## 🎯 Goals

Tools in this directory can be used to:

* download resources required for the build;
* generate files used by Senbit;
* convert resources into formats suitable for the system;
* prepare files for the root filesystem or ISO;
* automate repetitive build tasks.

Tools should remain **independent from the code executed by Senbit**, which is located in `src/`.

## ⌨️ Example: `keymaps`

`tools/keymaps` prepares the keyboard layouts used by the Senbit installer.

Its general workflow is:

```text
Keyboard map sources
        │
        ▼
   tools/keymaps
        │
        ├── download
        ├── convert
        └── validate
        │
        ▼
build/tools/generated/keymaps/
        │
        ▼
       build.sh
        │
        ▼
rootfs/usr/share/keymaps/
```

This allows Senbit to provide its own keyboard layouts without depending on the machine used to build the OS.

## 🧩 Convention for New Tools

Each tool should have its own directory and its own `Cargo.toml`.

Example:

```text
tools/
├── keymaps/
│   ├── Cargo.toml
│   └── src/
│       └── main.rs
│
├── packages/
│   ├── Cargo.toml
│   └── src/
│       └── main.rs
│
└── ...
```

Temporary and generated files should be written to:

```text
build/tools/
```

and not directly into the project's source directories.

## 🦀 Why Rust?

These tools are written in Rust to:

* avoid unnecessary reliance on complex shell scripts;
* provide proper error handling;
* make file and directory manipulation straightforward;
* keep the tools consistent with the Senbit ecosystem;
* allow tools to be reused outside of `build.sh`.

For example, creating a directory hierarchy can be done directly in Rust:

```rust
std::fs::create_dir_all("build/tools/generated/keymaps")?;
```

This is equivalent to using `mkdir -p`.

## 🔧 Usage

Tools can be executed directly with Cargo.

For example:

```bash
cargo run --manifest-path tools/keymaps/Cargo.toml
```

Eventually, `scripts/build.sh` will automatically run the required tools before building the root filesystem and ISO.

## 📌 General Rule

> `tools/` contains **how resources are generated**.
> `build/tools/generated/` contains **what has been generated**.
> `assets/` contains static project resources.
> `src/` contains the code executed by Senbit.
