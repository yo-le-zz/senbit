Roadmap

Organized by capability, not by date: a version is released when its goal is reached. Priorities: recovery and security, then declarative deployment, then real hardware. Until then, the target stays QEMU.

Done

0.1 – 0.3 · Foundation and server basics

  • Build system, Linux kernel, senbit-init, BIOS and UEFI boot
  • Installer, login, native commands, logging
  • Real apt and dpkg with Debian 12 packages
  • systemd as PID 1, systemctl, journalctl
  • DHCP and static networking, SSH with apt install openssh-server

0.4 · System updates

  • senbit-kernel and senbit-userspace packages
  • Signed update repository on GitHub Pages
  • apt upgrade, snapshot before an update
  • Automatic rollback after 3 failed boots
  • The rollback command

0.6 — Recovery and security (in progress)

A Senbit that fails can be repaired without reinstalling, and a server that is safe by default.

  • Recovery boot entry in GRUB (root shell)
  • Repair from the ISO: find an installed Senbit, mount it, shell inside
  • snapshot command: create, list, show, restore, delete
  • Filesystem check of the root partition at every boot
  • System API, a real panic command, panic hooks, panic=10
  • More consoles (Alt+F2, Alt+F3), job control
  • Firewall: nftables in the image, default ruleset, your own rules in /etc/senbit/firewall.d/
  • Exposure report: bootreport --ports, count in the login banner
  • File integrity: bootreport --verify, checked once per boot
  • Hardening defaults (sysctl, SSH without root login), sudo lockout
  • Opt-in automatic upgrades (timer, off by default)
  • Confirm Docker Engine networking in a VM

Done when: a broken /etc/fstab is repaired from the recovery entry or the ISO, snapshot restore undoes a configuration change, sudo panic ends with the machine back on its feet, a fresh install has a firewall, and a modified packaged file is reported at the next login.

0.7 — Declarative deployment

Install the same server twice, without answering questions.

  • Unattended install from an answers file
  • Export the answers of an installation to that file
  • VM disk image (devtool build image)
  • Published checksum for every ISO and image

Done when: one command creates a VM, installs Senbit with no question, and ends with a working login and SSH.

0.8 — Real hardware

Boot and install on one physical x86_64 machine.

  • Boot the ISO from a USB stick on a real PC, in UEFI mode
  • Review the kernel drivers: storage and common network cards
  • Decide how firmware files are handled
  • Document what is not supported (Secure Boot, to start with)
  • A hardware test checklist and the list of machines tried

Done when: a complete installation, a reboot, an update and a rollback were done on a physical machine.

Later, not planned

ARM64 and other architectures, management of several machines, remote administration, a declarative configuration of the running system, and Btrfs or LVM snapshots of the whole disk. Taken up only when the milestones above are done.

Full details: docs/ROADMAP.md.
