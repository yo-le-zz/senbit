Architecture

What Senbit is made of, and what happens from power-on to login.

Rust userspace on a standard base

Senbit init

PID 1, written in Rust in small modules (hostname, keymaps, network, installer). It prepares the system, then starts systemd.

Native commands

One Rust crate per command: sudo, log, bootreport, findmnt, adduser, useradd, getent and the power commands.

Standard tools

systemd for services, BusyBox for the minimal environment, and the real apt and dpkg for packages. No Senbit-specific wrapper.

From power-on to login

Senbit init runs as PID 1. Without an installation it starts the installer; otherwise it brings the installed system up in this order.

  1. Detect the system disk and mount the root filesystem
  2. Mount /proc, /sys, /dev and /run
  3. Verify /etc/fstab
  4. Initialize the hostname and the system configuration
  5. Initialize the networka failure never stops the boot: it is shown by bootreport at login
  6. Start the system infrastructure (systemd and the services)
  7. Log in, then start the user's shell

One ISO, two firmwares

The ISO

Hybrid image. GRUB i386-pc handles BIOS, GRUB x86_64-efi handles UEFI, and both lead to the same Senbit Linux.

BIOS installs

MBR partition table, ext4 root, GRUB with the i386-pc target.

UEFI installs

GPT table with a FAT32 EFI System Partition, ext4 root, GRUB with the x86_64-efi target.

Full technical documentation: docs/ in the repository.
