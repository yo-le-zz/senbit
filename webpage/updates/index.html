System updates

Senbit has no update command of its own: the system is updated with the real apt.

Updating

sudo apt update
sudo apt upgrade

Two Debian packages carry Senbit: senbit-kernel (kernel and init) and senbit-userspace (login, commands, systemd units, scripts). They are published in a GPG-signed APT repository and verified by apt like any other package.

Around an update

Detection

A daily timer checks for updates. bootreport tells you at login. Nothing is installed without you, and nothing is asked at boot.

Snapshot

Before each update, the configuration and the package state are saved in /var/lib/senbit/snapshots (the last three are kept). The snapshot command lists and restores them.

Previous version kept

The previous kernel and initramfs stay on disk and in the boot menu as “previous version”.

Automatic rollback

After three failed boots in a row, GRUB starts the previous version by itself, and the choice is kept for the next boots.

The rollback command

sudo rollback
rollback --status

sudo rollback shows the state and asks before going back to the previous version. Run it again to go forward. After a rollback, senbit-kernel is put on hold so that apt upgrade does not bring the faulty version back.

Use the repository

The images built with an [update] section in config.toml already contain this source:

Types: deb
      URIs: https://yo-le-zz.github.io/senbit
      Suites: stable
      Components: main
      Signed-By: /usr/share/keyrings/senbit-archive-keyring.gpg
